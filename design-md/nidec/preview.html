WEIGHT可変フォントの中間値で設計する

Noto Sans JP を wght@100..900 の可変フォントとして読み込んでいるので、--font-weight-250 と --font-weight-350 という中間値がトークンとして存在し、実際に描画される（実測: 欧文幅が 9 ウェイトすべて別の値 — 425.28 / 430.5 / 435.7 / 450.67 / 461.73 / 468.89 / 476.05 / 483.2 / 490.38px）。本文は 400 ではなく 350。400 に丸めるとサイトの軽さが消える。

TOKENSサイズ・行間・字間・ウェイトを 1 組で当てる

命名は --text-{pc|sp}-{jp}-{要素}-{ウェイト名}-{変種}。画面（pc/sp）と言語（jp）と、書体のウェイト名（demilight ＝ 350）と、行間の変種（narrow ＝ 130% / 無印 ＝ 170%）を名前に畳み込む。

この段落が --text-pc-jp-text-p-demilight-narrow（17px / 130% / 0 / 350）。4 つのトークンを必ずまとめて当てる。

この段落が --text-pc-jp-text-p-demilight-s（14px / 170% / 0 / 350）。narrow が付かない方は行間が広い。同じウェイトでも行間だけが違う 2 つが用意されている。

SCALING設計幅に対する vw で全寸法を書く

サイズの書き方calc(カンプのpx / var(--design-width) * 100vw)
--design-width1468（768px 以上）／ 376（767px 以下）。1440 と決め打ちしない
html の実測1440 / 1200 / 1024 / 834 / 768px → すべて 16px ／ 767px → 32.6383px ／ 375px → 15.9574px
注意768px と 767px の間でルートが 2.04 倍に跳ぶ。1440 / 1200 / 834 / 375px の 4 幅だけ測ると完全固定に見える
要素（トップの h2）1440 / 1200px → 48px（固定）／ 1024px → 33.4823px ／ 834px → 27.2698px ／ 768px → 25.1117px ／ 767 / 375px → 30px（固定）
三段構えデスクトップは px 固定、タブレット帯（768〜1024px）は要素側が vw で縮み、モバイルはルートが vw になる
余白・角丸すべて --spacing: calc(1 / 16 * 1rem) の倍数。--radius-4〜34、ボタンは 34px のピル形
ハーフレディング--leading-trim-v2: calc((1em - 1lh) / 2) — 1lh 単位を使う

CAUTION再現するときの注意

  • font-weight: 350 を 400 に丸めない。250・350 は可変フォント前提で設計された値
  • font-weight: 600 を使わない。--font-weight-* のトークンに存在しない（実測 7 要素は設計外）
  • --design-width を 1440 と決め打ちしない。デスクトップ 1468 / モバイル 376
  • 768px / 767px を跨ぐテストを省かない。ルートが 16px → 32.6px に跳ぶ
  • rem だけでレスポンシブを作らない。デスクトップ帯はルートが固定で、要素側の vw が応答する
  • palt を「不要」と読まない。可視 190 要素すべて normal だが、書体は対応しており足せば約 14% 詰まる（実測 540px → 463.09px）
  • 文字色・区切り線に純粋な無彩色のグレーを使わない。実サイトのグレーには緑が入っている（#8f9c95 #c7cdca #5e8370）
  • document.fonts に unloaded が大量（@font-face 351 件）に出るのは、Google Fonts が和文を unicode-range で分割するため。異常ではない
